# Installation (English)

1. **Inspect hardware:** The example expects ESP32-C3 Zero and 4S JBD DP04S007-L4S. Match actual logic levels and pinout; see HARDWARE.md.
2. **Keep secrets local:** Copy `secrets.yaml.example` to your local ESPHome configuration directory as `secrets.yaml`, then set credentials. If ESPHome already holds these secrets, reuse them. Never push your `secrets.yaml` to GitHub.
3. **Choose firmware language:** `firmware/jbd-bms-en.yaml` or `firmware/jbd-bms-ua.yaml`. This only changes runtime status messages, not entity IDs or BMS commands.
4. **Review device name and pin mapping:** Default `esphome.name: jbd-bms`, `friendly_name: JBD-BMS`, GPIO4 TX and GPIO5 RX, 9600 baud, ESP-IDF, and `!secret jbd_bms__encryption_key`.
5. **Validate firmware:** From an ESPHome configuration directory, run `esphome config jbd-bms.yaml` (or ESPHome Device Builder → Validate). Then flash using the standard ESPHome installation flow. **Validation and compilation must be run on your environment.**
6. **Verify monitoring:** Check four series-group voltages, pack voltage, current and BMS Online in Home Assistant.
7. **Install a dashboard:** Home Assistant → Dashboards → edit a user-controlled dashboard → raw configuration editor → paste the **entire** `dashboards/jbd-dashboard-en.yaml` or `-uk.yaml`. Do not paste six top-level views as a single card.
8. **Check entity IDs:** `jbd_bms_` entities are based on the example device name. Existing installations with suffixed names or duplicate entities may need manual entity ID mapping.
9. **Read EEPROM:** Open EEPROM tab, press Read All 10 Parameters, wait for `Read 10/10; exit confirmed; NO WRITE`. Read again after each ESP restart before comparison.
10. **Profiles:** Profiles → modify a custom profile, save, unlock DRAFT, load the profile, validate. This does not write BMS EEPROM. APPLY on Settings is a separate deliberate action.

## Language behavior

Dashboard YAML controls view titles, labels, confirmations and guidance text. **Profile operation status sensors are generated by the ESP32 firmware.** To capture screenshots with all profile statuses in English, select the English firmware variant. Changing only Dashboard YAML does not translate telemetry text already emitted by ESP32.

## First-run troubleshooting

- `unknown`: EEPROM data was not read during this ESP32 session. Use Read All 10 Parameters.
- Missing entities: Compare IDs in HA Developer Tools → States against `jbd_bms_*`; check device name, duplicates, and disabled-by-default diagnostic entities.
- ESP32 boots but no UART telemetry: confirm signal TX→RX, RX←TX, GND reference, correct electrical logic and external component version. Do not assume UART pin labels on all BMS revisions are interchangeable.
- Firmware cannot fetch external component: check network access to GitHub and the upstream repository.
- Language changed but status messages remain Ukrainian: those strings come from UA firmware; use the EN firmware when needed.


## UART baseline for published beta

The tested configuration uses `logger.level: WARN`, `update_interval: 5s` and `rx_timeout: 300ms`. To troubleshoot, temporarily use `INFO` logging with caution; publishing DEBUG logs may expose hardware identifiers.
